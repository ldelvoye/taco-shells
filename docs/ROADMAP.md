# Features

- Settings tab: `cmd+,` opens a tab with a control for every setting (theme, font and size, cursor, scrollback, restore on launch) instead of opening `settings.json` in `$EDITOR` in a new terminal. The file stays the source of truth: a change in the tab is written back to it and applies live, the same as a hand edit, so the write has to keep the comments and formatting the user put in the file. Keybindings can follow as a second section once settings work.
- Which agent a terminal is running, at a glance. Once a second agent is supported and people run two side by side, a row should show whether it holds Claude Code, Codex or another agent, for instance an icon per agent beside the session marker. Grouping terminals by agent automatically could build on the same thing. Waits for a second harness: Claude Code is the only one today, so there is nothing to tell apart.

# Distribution

- An install a stranger can finish. A dmg downloaded in a browser reports as damaged until the `xattr` command in the README is run. Candidates: an install script served from the site (a file fetched by `curl` is not quarantined, which needs confirming on a Mac with Gatekeeper on), or signing and notarising with a Developer ID. The other half is done: the app now wires Claude Code's hooks itself, from the installed copy. This comes before the release page, which can only show the install that exists.
- Release page at `tacoshells.dev`: a page whose job is to get someone who has never heard of Taco Shells to a working install. It leads with what the app does and how to install it, and its download points at GitHub's `/releases/latest`, which is already the stable link. The domain is not bought yet; it was open on Namecheap on 2026-11-23. Still to decide: where the page's source lives and where it is hosted.

# Architecture

- Model operations share their lookups. `shared/model.ts` finds a pane's group and index the same way in seven functions, replaces the group at an index in eight, and rebuilds lists by slicing in about ten. Three helpers remove the repetition, and `applyDrop` with its helpers moves to its own module, where `moveGroup` can stop being an export that is unsafe to call on its own.
- Workspace state out of `App.tsx`. One component holds the workspace, the agent rows, the waiting terminal and command registration, and about twenty of its callbacks only forward to a model operation. A workspace reducer, with hooks for the agent rows and for attention, takes that out. It also removes the two state updaters that set a ref as a side effect, the refs that mirror state, and the re-registering of every command each time the workspace changes.
- Sidebar in pieces. `Sidebar.tsx` is one 750-line component. It should receive the workspace whole instead of rebuilding it from three props. The code that decides where the drop line is drawn is pure and untested, and belongs beside `shared/drop.ts` with tests. A row, a tab group's section and the drag handling are each their own piece. Easier once the workspace state has moved.
- One banner and one popup. The config, update and agent strips share their look by wearing each other's class names, and the tab group popup does the same with the row popup's. A `Banner` component and neutral popup class names replace that, and `app.css` is reordered under section comments rather than split. This includes renaming `RowColorPicker`: it is the whole right-click popup of a row now, and holds Fork with Claude beside the color dots, so the component, its file and its props should be named for the popup, not for the colors.
- Main's services start and stop one way. `registerFocus`, `registerUpdates` and `registerAgents` each return a different shape, kept in five variables in `main/index.ts`. `registerAgents` is a 215-line closure that reads the agent's settings file and the app's record three times per refresh. One shape for all of them, and one read per refresh.
- The legacy session routes go. Claude's hook script posts to `/agent-session/*` now, and the focus server still answers `/claude-session/*` for copies of the script from before that. Delete those routes once no hand-wired setup points at an older copy.

# Tests

- The silent decisions are pinned. Three have no test that would notice their removal: the snapshot ignoring pty exits once the app is quitting, which is what keeps agent sessions in the last save; the key-code mapping behind `cmd+opt+1` to `6`; and the updater skipping a release that is not newer.
- Tests that do not earn their place are cut. About ten unit assertions copy a literal from the source or repeat a neighbouring case, and six e2e checks assert again what the model's own tests already pin; each of those keeps only the half proving a chord reaches the screen. Two tests whose name promises more than they assert get a truthful name, the test for declining gains the one line proving the written entries are left alone, and the five unit files that never remove their temp directories get a shared helper. Not worth doing: a fake `node-pty` to test `sessions.ts`, a test for the updater's startup pruning, sharing workspace builders across test files, or sharing one app between e2e tests.
- e2e harness in pieces. `e2e/app.ts` is a 1,000-line file around one 536-line function, and every helper is named three times. It splits along its seams: keys, the DevTools connection, reading the screen, mouse and drag input, and the app's lifecycle. Helpers only one test file uses move beside it, and `rightClickHeader`, `clickUngroupItem` and `dragHeader` have no caller and go. The refused-split test waits half a second after each of ten presses and needs one wait.
